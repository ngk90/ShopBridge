# API Endpoints

ShopBridge exposes a RESTful API for managing inventory items. All endpoints follow standard HTTP conventions and return JSON responses. The API is built with ASP.NET Core and uses dependency injection to integrate with the repository layer for data access.

## Base URL

All endpoints are prefixed with `/api/inventory`.

## Inventory Endpoints

The Inventory Controller (`ShopBridge/Controllers/InventoryController.cs`) provides four core operations for managing inventory items:

| Method | Endpoint | Description |
|--------|----------|-------------|
| GET | `/api/inventory` | Retrieve all inventory items |
| POST | `/api/inventory` | Create a new inventory item |
| PUT | `/api/inventory` | Update an existing inventory item |
| DELETE | `/api/inventory` | Delete an inventory item by ID |

## Request & Response Formats

### InventoryDto

All inventory operations use the `InventoryDto` data transfer object (`ShopBridge/DTO/InventoryDto.cs`):

```csharp
public class InventoryDto
{
    public int? Id { get; set; }
    [Required]
    public string Name { get; set; }
    [Required]
    public string Description { get; set; }
    [Required]
    public decimal? Price { get; set; }
}
```

**Field Descriptions:**
- **Id** (optional): Unique identifier; auto-generated on creation, required for updates and deletes
- **Name** (required): Product name
- **Description** (required): Product description
- **Price** (required): Product price as a decimal value

### POST /api/inventory

Creates a new inventory item.

**Request:**
```
POST /api/inventory
Content-Type: application/json

{
  "name": "Keyboard",
  "description": "Mechanical keyboard",
  "price": 149.99
}
```

**Response (200 OK):**
```
OK
```

**Response (400 Bad Request):**
```json
{
  "error": "Error while adding new resource"
}
```

**Validation:** All fields (`Name`, `Description`, `Price`) are required. The request will fail with a 400 status and ModelState errors if validation fails.

### PUT /api/inventory

Updates an existing inventory item.

**Request:**
```
PUT /api/inventory
Content-Type: application/json

{
  "id": 1,
  "name": "Laptop Pro",
  "description": "Updated high-performance laptop",
  "price": 1299.99
}
```

**Response (200 OK):**
```
OK
```

**Response (400 Bad Request):**
```json
{
  "error": "Error while editing resource"
}
```

**Note:** The `Id` field is required for updates. All required fields must be provided.

### DELETE /api/inventory

Deletes an inventory item by ID.

**Request:**
```
DELETE /api/inventory?id=1
```

**Response (200 OK):**
```
OK
```

**Response (400 Bad Request):**
```json
{
  "error": "Error while removing resource"
}
```

**Parameters:**
- **id** (query, required): The ID of the item to delete. Must be greater than 0.

## Error Handling

All endpoints return standardized HTTP status codes:

| Status Code | Meaning |
|-------------|---------|
| 200 | Success |
| 400 | Bad Request (validation failure, invalid parameters, or operation error) |

When a request fails, the response body contains either a descriptive error message or ModelState validation errors detailing which fields are invalid.

## Data Validation

- **Required Fields:** `Name`, `Description`, and `Price` are mandatory for POST and PUT requests
- **ID Validation:** DELETE requires `id > 0`
- **ModelState Validation:** All endpoints validate the DTO before processing; invalid requests return 400 with ModelState details

## Integration with Repositories

Each endpoint delegates business logic to the `IInventoryRepository` interface, which is injected via the constructor. The controller handles HTTP concerns (routing, status codes, serialization) while the repository manages data access operations.
