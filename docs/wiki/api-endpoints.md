# API Endpoints

ShopBridge exposes a RESTful API for managing inventory items through the `InventoryController`. All endpoints are prefixed with `/api/inventory` and support standard HTTP methods (GET, POST, PUT, DELETE). The API is fully documented with Swagger/OpenAPI, accessible at the root path (`/`) when the application runs in development mode.

## Base URL

```
https://localhost:5001/api/inventory
```

Swagger documentation is available at `https://localhost:5001/` in development environments.

## Endpoints

### Get All Inventory Items

Retrieves a list of all inventory items in the system.

| Property | Value |
|----------|-------|
| **Method** | GET |
| **Route** | `/api/inventory` |
| **Authentication** | None |
| **Response** | Array of inventory items |

**Example Request:**
```bash
GET /api/inventory
```

**Example Response (200 OK):**
```json
[
  {
    "id": 1,
    "name": "Laptop",
    "description": "High-performance laptop",
    "price": 999.99
  },
  {
    "id": 2,
    "name": "Mouse",
    "description": "Wireless mouse",
    "price": 29.99
  }
]
```

### Create Inventory Item

Adds a new inventory item to the system. The request body must contain valid `InventoryDto` data.

| Property | Value |
|----------|-------|
| **Method** | POST |
| **Route** | `/api/inventory` |
| **Content-Type** | `application/json` |
| **Response** | 200 OK on success, 400 Bad Request on validation failure |

**Request Body (`InventoryDto`):**
- `name` (string, required): Product name
- `description` (string, required): Product description
- `price` (decimal, required): Product price

**Example Request:**
```bash
POST /api/inventory
Content-Type: application/json

{
  "name": "Keyboard",
  "description": "Mechanical keyboard",
  "price": 149.99
}
```

**Example Response (200 OK):**
```
OK
```

**Example Error Response (400 Bad Request):**
```json
{
  "error": "Error while adding new resource"
}
```

### Update Inventory Item

Modifies an existing inventory item. The `Id` field in the request body identifies which item to update.

| Property | Value |
|----------|-------|
| **Method** | PUT |
| **Route** | `/api/inventory` |
| **Content-Type** | `application/json` |
| **Response** | 200 OK on success, 400 Bad Request on validation failure |

**Request Body:**
- `id` (integer, required): Item identifier
- `name` (string, required): Updated product name
- `description` (string, required): Updated product description
- `price` (decimal, required): Updated product price

**Example Request:**
```bash
PUT /api/inventory
Content-Type: application/json

{
  "id": 1,
  "name": "Gaming Laptop",
  "description": "High-performance gaming laptop",
  "price": 1299.99
}
```

**Example Response (200 OK):**
```
OK
```

### Delete Inventory Item

Removes an inventory item from the system by its ID.

| Property | Value |
|----------|-------|
| **Method** | DELETE |
| **Route** | `/api/inventory` |
| **Query Parameter** | `id` (integer, required) |
| **Response** | 200 OK on success, 400 Bad Request if ID is invalid |

**Example Request:**
```bash
DELETE /api/inventory?id=1
```

**Example Response (200 OK):**
```
OK
```

**Example Error Response (400 Bad Request):**
```json
{
  "error": "No Data found!"
}
```

## Request/Response Models

### InventoryDto

The `InventoryDto` class (`ShopBridge/DTO/InventoryDto.cs`) defines the structure for inventory items:

```csharp
public class InventoryDto
{
    public int? Id { get; set; }
    [Required]
    public string Name { get; set; }
    [Required]
    public string Description { get; set; }
    [Required]
    public decimal? Price { get; set; }
}
```

- **Id**: Optional; auto-generated on creation, required for updates
- **Name**: Required; product name
- **Description**: Required; product details
- **Price**: Required; product cost

## Implementation Details

The API is implemented in `ShopBridge/Controllers/InventoryController.cs` and uses:

- **Dependency Injection**: `IInventoryRepository` is injected for data access
- **Async/Await**: All operations are asynchronous for better performance
- **Model Validation**: Request bodies are validated using `ModelState.IsValid`
- **Error Handling**: Global error handling middleware processes exceptions

All endpoints return operation status (1 for success, other values for failure) from the repository layer, which is translated to appropriate HTTP responses.
