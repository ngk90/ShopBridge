ShopBridge is an ASP.NET Core web API designed for inventory management, built with Entity Framework Core for data access and SQL Server for persistent storage. It provides a RESTful interface for managing inventory operations with automated error handling, API documentation via Swagger, and dependency injection for clean architecture.

## Technology Stack

ShopBridge is built on modern .NET technologies:

| Component | Technology | Version |
|-----------|-----------|---------|
| Framework | ASP.NET Core | 3.1 |
| ORM | Entity Framework Core | 5.0.0 |
| Database | SQL Server | - |
| API Documentation | Swagger/Swashbuckle | 6.1.4 |
| Object Mapping | AutoMapper | 8.1.1 |

## Key Features

- **RESTful API**: Full-featured HTTP endpoints for inventory operations
- **Entity Framework Core Integration**: Type-safe database access with LINQ support
- **SQL Server Backend**: Reliable relational database for data persistence
- **Swagger UI**: Interactive API documentation available at the root endpoint
- **Global Error Handling**: Centralized middleware for consistent error responses
- **Dependency Injection**: Built-in IoC container for loose coupling and testability
- **AutoMapper Support**: Automatic DTO-to-model mapping for clean data transfer

## Project Structure

The main application resides in `ShopBridge/` with the following key directories:

- **Controllers**: HTTP endpoint handlers
- **Models**: Domain entities representing inventory data
- **DTO**: Data Transfer Objects for API requests and responses
- **Repositories**: Data access layer abstractions
- **Middlewares**: Custom HTTP middleware including error handling
- **Migrations**: Entity Framework Core database schema migrations

## Getting Started

The application is configured in `ShopBridge/Startup.cs` where services are registered and the HTTP pipeline is configured. The database context (`InventoryDBContext`) is initialized with SQL Server using a connection string from configuration. Swagger UI is automatically enabled and serves as the default landing page for API exploration.

## Configuration

Connection strings and application settings are managed through `appsettings.json` and `appsettings.Development.json`. The project uses user secrets for sensitive configuration during development (User Secrets ID: `88f89ce7-8f56-4d82-96a4-e2f62cea5b32`).
