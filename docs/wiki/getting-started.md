# Getting Started

_Generated by Forge from `main` at `8a6ac81`._

This page guides you through setting up the ShopBridge development environment, configuring the database connection, and running the application locally. ShopBridge is an ASP.NET Core web API built with Entity Framework Core and SQL Server, featuring Swagger documentation and a global error handling middleware.

## Prerequisites

Before you begin, ensure you have the following installed:

- **.NET SDK** (version 5.0 or later) — [Download](https://dotnet.microsoft.com/download)
- **SQL Server** (Express or Developer Edition) — [Download](https://www.microsoft.com/sql-server/sql-server-downloads)
- **Visual Studio** 2019+ or **Visual Studio Code** with C# extension
- **Git** for cloning the repository

## Clone the Repository

```bash
git clone https://github.com/ngk90/ShopBridge.git
cd ShopBridge
```

## Configure the Database Connection

The application uses SQL Server as its database. Configuration is managed through `appsettings.json` and `appsettings.Development.json`.

### 1. Update Connection String

Edit `ShopBridge/appsettings.json` and update the `DefaultConnection` with your SQL Server credentials:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=YOUR_SERVER;Initial Catalog=YOUR_DATABASE;Persist Security Info=True;User ID=YOUR_USER;Password=YOUR_PASSWORD"
  }
}
```

**Connection string parameters:**

| Parameter | Description |
|-----------|-------------|
| `Data Source` | SQL Server instance name or IP address |
| `Initial Catalog` | Database name (will be created by migrations) |
| `User ID` | SQL Server login username |
| `Password` | SQL Server login password |

### 2. Development Configuration

The `ShopBridge/appsettings.Development.json` file contains environment-specific settings for development. It inherits logging configuration from the base settings file:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft": "Warning",
      "Microsoft.Hosting.Lifetime": "Information"
    }
  }
}
```

## Restore Dependencies and Build

Open a terminal in the repository root and run:

```bash
dotnet restore
dotnet build
```

This restores NuGet packages and compiles the solution.

## Apply Database Migrations

ShopBridge uses Entity Framework Core migrations to manage the database schema. Apply pending migrations:

```bash
cd ShopBridge
dotnet ef database update
```

This creates the database and tables defined in `InventoryDBContext.cs`.

## Run the Application

Start the development server:

```bash
dotnet run
```

The application will start on `https://localhost:5001` (or the port specified in your launch settings).

## Access Swagger Documentation

Once running, open your browser and navigate to:

```
https://localhost:5001
```

Swagger UI is configured as the default route and displays all available API endpoints with interactive documentation. You can test endpoints directly from the browser.

## Project Structure

| Directory | Purpose |
|-----------|---------|
| `Controllers/` | API endpoint handlers |
| `Models/` | Entity models for the database |
| `DTO/` | Data Transfer Objects for request/response payloads |
| `Repositories/` | Data access layer implementations |
| `Middlewares/` | Custom middleware (e.g., error handling) |
| `Migrations/` | Entity Framework Core migration files |

## Verify the Setup

To verify your setup is working:

1. The application starts without errors
2. Swagger UI loads at `https://localhost:5001`
3. Database migrations complete successfully
4. You can see API endpoints listed in Swagger

If you encounter issues, check:

- SQL Server is running and accessible
- Connection string credentials are correct
- .NET SDK version matches project requirements
- Firewall allows connections to SQL Server
