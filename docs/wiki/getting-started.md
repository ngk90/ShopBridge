# Getting Started

This guide walks you through setting up the ShopBridge development environment, configuring the database connection, and running the application locally. ShopBridge is an ASP.NET Core 3.1 web API built with Entity Framework Core and SQL Server.

## Prerequisites

Before you begin, ensure you have the following installed:

- **.NET Core 3.1 SDK** or later ([download](https://dotnet.microsoft.com/download))
- **SQL Server** (Express or Developer Edition) or **SQL Server LocalDB**
- **Visual Studio 2019+** or **Visual Studio Code** with C# extension
- **Git** for cloning the repository

## Clone the Repository

```bash
git clone https://github.com/ngk90/ShopBridge.git
cd ShopBridge
```

## Project Structure

The solution contains two projects:

| Project | Purpose |
|---------|---------|
| `ShopBridge` | Main ASP.NET Core web API application |
| `ShopBridge.UnitTest` | Unit tests for the application |

## Configure the Database Connection

### 1. Update Connection String

Edit `ShopBridge/appsettings.json` to set your SQL Server connection details:

```json
{
  "ConnectionStrings": {
    "DefaultConnection": "Data Source=YOUR_SERVER;Initial Catalog=YOUR_DATABASE;Persist Security Info=True;User ID=YOUR_USER;Password=YOUR_PASSWORD"
  }
}
```

**Common connection string examples:**

- **Local SQL Server:** `Data Source=localhost;Initial Catalog=ShopBridge;Integrated Security=True`
- **SQL Server Express:** `Data Source=.\SQLEXPRESS;Initial Catalog=ShopBridge;Integrated Security=True`
- **LocalDB:** `Data Source=(localdb)\mssqllocaldb;Initial Catalog=ShopBridge;Integrated Security=True`

### 2. Development Configuration

The `ShopBridge/appsettings.Development.json` file contains environment-specific settings. In development, it inherits the base configuration and can override logging levels:

```json
{
  "Logging": {
    "LogLevel": {
      "Default": "Information",
      "Microsoft": "Warning",
      "Microsoft.Hosting.Lifetime": "Information"
    }
  }
}
```

## Restore Dependencies and Build

Navigate to the project directory and restore NuGet packages:

```bash
cd ShopBridge
dotnet restore
```

Build the solution:

```bash
dotnet build
```

## Apply Database Migrations

ShopBridge uses Entity Framework Core migrations to manage the database schema. Apply pending migrations:

```bash
dotnet ef database update
```

This command:
- Creates the database if it doesn't exist
- Applies all pending migrations from the `Migrations` folder
- Initializes the schema based on the `InventoryDBContext` model

If you need to create a new migration after modifying models:

```bash
dotnet ef migrations add MigrationName
```

## Run the Application

Start the development server:

```bash
dotnet run
```

The application will start on `https://localhost:5001` by default. You'll see output similar to:

```
info: Microsoft.Hosting.Lifetime[0]
      Now listening on: https://localhost:5001
```

## Access the API Documentation

ShopBridge includes **Swagger UI** for interactive API documentation. Once the application is running, open your browser and navigate to:

```
https://localhost:5001
```

Swagger UI displays all available endpoints, request/response schemas, and allows you to test endpoints directly.

To verify your setup is complete:

1. **Check database connection:** Run `dotnet ef database update` without errors
2. **Start the application:** Run `dotnet run` and confirm it starts successfully
3. **Access Swagger UI:** Navigate to `https://localhost:5001` and see the API documentation
4. **Test an endpoint:** Use Swagger UI to call a test endpoint (e.g., GET `/api/inventory`)

## Troubleshooting

| Issue | Solution |
|-------|----------|
| **Connection string error** | Verify SQL Server is running and credentials are correct in `appsettings.json` |
| **Migration fails** | Ensure the database exists or remove `Initial Catalog` from the connection string to auto-create it |
| **Port already in use** | Change the port in `launchSettings.json` or stop the process using port 5001 |
| **NuGet restore fails** | Clear the NuGet cache: `dotnet nuget locals all --clear` |
